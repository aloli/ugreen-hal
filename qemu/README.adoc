= Banc de test QEMU — compilation FreeBSD
:toc:
:sectnums:

Banc de compilation FreeBSD local, sur la machine de développement. Livrable de l'environnement de développement prévu au sprint 1 du plan de projet.

== À quoi il sert, et à quoi il ne sert pas

[cols="1,3"]
|===
|Il permet |Il ne permet pas

|Compiler `src/cli/` contre les *véritables* en-têtes FreeBSD (`dev/smbus/smb.h`), ce que la machine de développement — un Mac — ne peut pas faire.
|Valider le protocole SMBus. Le contrôleur LED d'UGREEN est un composant physique de la carte mère : il ne s'émule pas.

|Produire un binaire *FreeBSD/amd64*, directement copiable sur le DXP2800.
|Dire si une LED s'allume. C'est le travail du sprint 3.3, sur le matériel réel.

|Vérifier que `struct smbcmd` est correctement remplie et que les ioctls existent.
|Remplacer le NAS. Aucune émulation ne reproduit une carte mère UGREEN.
|===

=== Bonus constaté le 21/07/2026 : le SMBus est émulé

La machine `q35` de QEMU expose un contrôleur SMBus ICH9, auquel `ichsmb(4)` s'attache — le pilote même que vise le code sur le DXP2800 :

[source]
----
ichsmb0: <Intel 82801I (ICH9) SMBus controller> port 0x6100-0x613f irq 16 at device 31.3 on pci0
smbus0: <System Management Bus> on ichsmb0
----

Le banc permet donc davantage qu'une simple compilation : toute la *plomberie* devient vérifiable — ouverture de `/dev/smb0`, acceptation des ioctls par le noyau, remontée propre des erreurs. C'est l'objet de `30-smoke-test.sh`.

La seule inconnue qui subsiste après ce banc est le dialogue avec le microcontrôleur UGREEN lui-même : aucun périphérique ne répond à l'adresse `0x74` dans une VM. Dans ce test, *l'échec est le résultat attendu* — ce qu'on éprouve, c'est la qualité du message d'erreur, pas l'allumage d'une LED.

== Pourquoi amd64 plutôt qu'aarch64

Le banc voisin (`prod-crystal/qemu`, projet clevis-zfs) utilise une image *aarch64*, qui bénéficie de l'accélération matérielle HVF sur Mac Apple Silicon et démarre en quelques secondes.

Ce banc-ci est en *amd64*, délibérément : le DXP2800 est un Intel N100, et l'intérêt principal est de produire un binaire directement exécutable sur le NAS. Contrepartie assumée : sur un Mac ARM, l'amd64 tourne en émulation logicielle (TCG), sans accélération — le démarrage prend plusieurs minutes. C'est sans importance pour l'usage visé : on compile 300 lignes de C, pas un `buildworld`.

Les deux bancs peuvent tourner simultanément : celui-ci utilise le port SSH 2224, les ports 2222 et 2223 étant pris par clevis-zfs.

== Utilisation

[source,shell]
----
./00-fetch-image.sh    # 1re fois : ~600 Mo à télécharger
./01-prepare-vm.sh     # disque + ISO cloud-init
./10-run.sh            # démarre la VM en tâche de fond
./20-build.sh          # compile src/cli/ et rapatrie le binaire
./30-smoke-test.sh     # exerce le binaire dans la VM (SMBus, erreurs)
./99-stop.sh           # arrête la VM
----

`10-run-console.sh` remplace `10-run.sh` quand on veut la console série attachée au terminal — pour provisionner une image sans cloud-init, ou pour voir défiler un démarrage qui n'aboutit pas.

Les scripts enchaînent les commandes dans la VM par SSH : rien à taper à la main dans le système invité.

Le binaire produit atterrit dans `qemu/build/ugreen-led-ctl-freebsd-amd64`.

Suivre le démarrage, qui est long :

[source,shell]
----
tail -f logs/builder.log
----

Se connecter à la VM à la main :

[source,shell]
----
ssh -i ssh/id_ed25519 -p 2224 freebsd@127.0.0.1
----

== Choisir la version de FreeBSD

La version est surchargeable, et ce n'est pas cosmétique : les cibles n'ont pas la même base. FreeBSD garantit la compatibilité *ascendante* — un binaire ancien tourne sur un système récent — mais jamais l'inverse.

[cols="1,1,3", options="header"]
|===
|Cible |Version à viser |Disponibilité

|zVault
|13.3-RELEASE
|Retirée des miroirs courants (FreeBSD 13 est en fin de vie), mais *présente sur `archive.freebsd.org`* — le banc l'y récupère automatiquement. Sans cloud-init, voir ci-dessous.

|XigmaNAS
|14.4-RELEASE
|Miroirs courants, avec cloud-init. Aucune manipulation particulière.

|Développement courant
|15.0-RELEASE
|Défaut. Combiné à l'édition de liens statique de `src/cli/`, convient à toutes les cibles dans la grande majorité des cas.
|===

[source,shell]
----
FREEBSD_VERSION=14.4-RELEASE ./00-fetch-image.sh
FREEBSD_VERSION=14.4-RELEASE ./01-prepare-vm.sh
FREEBSD_VERSION=14.4-RELEASE ./10-run.sh
----

=== Images sans cloud-init (FreeBSD 13 et antérieurs)

Les images antérieures à FreeBSD 14 n'ont pas de variante `BASIC-CLOUDINIT` : cette convention est postérieure. L'ISO de seed reste donc sans effet, aucune clé SSH n'est injectée, et `20-build.sh` ne peut pas se connecter.

Provisionnement manuel, une seule fois par disque :

[source,shell]
----
FREEBSD_VERSION=13.3-RELEASE ./10-run-console.sh
----

Puis, dans la console série — connexion `root`, sans mot de passe :

[source,shell]
----
sysrc sshd_enable=YES
service sshd start
mkdir -p /root/.ssh && chmod 700 /root/.ssh
# coller le contenu de qemu/ssh/id_ed25519.pub dans authorized_keys
----

Il faut ensuite adapter `run_ssh` dans `lib/common.sh` pour viser `root` plutôt que `freebsd`. Pour quitter QEMU depuis la console série : *Ctrl-A* puis *X*.

[TIP]
====
Cette manipulation ne se justifie que si l'on veut la correspondance exacte avec zVault. Pour le travail courant, une image 14.x ou 15.x combinée au binaire statique demande nettement moins de gestes pour un risque comparable — le statique supprimant la dépendance aux versions de symboles de la libc, qui est le mode d'échec réel.
====

== Remise à zéro

La VM est jetable. En cas de doute sur son état :

[source,shell]
----
./99-stop.sh
rm -f run/builder.qcow2
./01-prepare-vm.sh
./10-run.sh
----

L'image de base (`images/`) n'est pas touchée : seul le disque de travail est recréé.

== Prérequis

* `qemu` (`brew install qemu`) — fournit `qemu-system-x86_64`, `qemu-img` et le firmware EDK2.
* `hdiutil`, natif macOS, pour fabriquer l'ISO cloud-init.

Le chemin du firmware EDK2 est fixé dans `lib/common.sh` (`/opt/homebrew/share/qemu/edk2-x86_64-code.fd`) ; à ajuster sur une installation Homebrew non standard.

== Contenu non versionné

`images/`, `run/`, `logs/`, `ssh/` et `build/` sont ignorés par Git : ce sont des artefacts locaux, dont plusieurs Gio d'images disque.
